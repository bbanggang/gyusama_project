# 규사마 프로젝트 핵심 보고서

> 가상 시뮬레이션에서 만든 자율주행 AI를 실제 소형 로봇(TurtleBot3 + RPi5)에 옮겨 30 FPS로 실시간 주행시키기까지의 굵직한 15개 작업을 정리한 문서.
>
> 로봇·AI 비전공자도 흐름을 따라올 수 있도록 용어를 풀어썼습니다.

---

## 1. 자율주행 시스템 전체 설계

자율주행 로봇을 만들려면 카메라가 본 영상을 AI가 분석해 차선을 찾고, 그 결과를 모터 제어 명령으로 바꿔 보내는 큰 흐름이 필요합니다. 처음에는 어떤 모델로, 어떤 환경에서, 어떻게 학습시키고 어떻게 실제 로봇까지 옮길지 결정된 게 없었음. 가상 시뮬레이션에서 데이터를 모아 AI를 학습시키고 → 실물 로봇으로 옮긴 뒤 → 전용 가속기 칩까지 사용해 실시간으로 동작시키는 14주짜리 전체 로드맵을 그렸고, 이 큰 그림이 끝까지 모든 단계의 기준점이 되어 중간에 방향이 흔들리지 않도록 했습니다.

## 2. Docker 컨테이너 기반 멀티-노드 실행 환경

자율주행에는 카메라 영상 수집·AI 추론·장애물 감지·모터 제어 등 여러 프로그램이 동시에 돌아가야 하는데, 이들을 각자 설치하면 PC와 로봇의 환경 차이로 한쪽에서 잘 되는 게 다른 쪽에서 안 되는 일이 자주 생깁니다. 모든 프로그램과 의존성을 한 묶음으로 격리하는 **컨테이너(Docker)** 안에 4개 노드를 분리해 넣고, 한 줄의 명령으로 모든 노드를 동시에 띄울 수 있게 만들었습니다. 결과적으로 PC 시뮬레이션과 실물 로봇 양쪽이 동일한 환경에서 같은 코드로 동작하게 되어, 환경 차이로 인한 디버깅 시간이 크게 줄었습니다.

## 3. 가상 시뮬레이션 디지털 트윈 구축

실제 로봇에 처음부터 학습된 AI를 올리려면 시행착오 때마다 로봇이 움직여야 해 위험하고 시간이 많이 듭니다. 컴퓨터 안에 실제 트랙·로봇·카메라·거리 측정 센서까지 그대로 재현한 **디지털 쌍둥이(Isaac Sim)** 를 만들어, 실물 로봇과 같은 시야·움직임·물리 반응을 모니터 안에서 100% 똑같이 돌릴 수 있게 했습니다. 이 덕분에 모든 알고리즘을 컴퓨터 안에서 먼저 검증한 뒤 실물에 옮길 수 있게 되어, 실물 환경에서의 시행착오 횟수가 결정적으로 줄었습니다.

## 4. 학습용 합성 데이터 자동 생성 파이프라인

AI가 차선을 인식하도록 학습시키려면 수천 장의 라벨링된 이미지(이 부분이 차선이라고 표시된 사진)가 필요한데, 실물 사진을 일일이 찍고 표시하는 건 사람 손으로 며칠씩 걸립니다. 디지털 쌍둥이 안에서 카메라 위치·각도·조명·노이즈를 무작위로 바꿔가며 자동으로 **사진 2000장 + 위치 정보(라벨)** 를 동시에 생성하는 스크립트를 만들었습니다. 사람 손으로 표시할 필요 없이 다양한 환경 조건의 학습용 데이터를 단 몇 십 분에 완성하게 됐고, 시뮬과 실제 환경의 차이를 줄이는 데도 핵심 역할을 했습니다.

## 5. YOLOv8 기반 차선 인식 모델 학습 파이프라인

가상 환경에서 만든 데이터로 학습한 AI 모델을 소형 로봇(RPi5)에서 실시간으로 실행 가능하게 만들기 위해 학습 스크립트를 구현했습니다. 생성된 합성 데이터를 YOLOv8 모델에 자동으로 입력해 차선 인식을 학습시키고, 학습이 끝난 모델을 표준 형식(ONNX)으로 자동 저장하는 역할을 수행. 별도의 수작업 없이 데이터셋만 바꾸면 새 모델이 자동으로 학습·저장되는 파이프라인이 완성되어, 입력 크기나 모델 종류를 바꿔가며 반복 실험이 빨라졌습니다.

## 6. 차선 추종 제어 노드 구현

학습된 AI는 단순히 "사진 한 장에서 차선이 어디 있는가"를 알려주는 함수일 뿐이라, 카메라에서 영상이 들어와 모터 명령이 나가는 전체 흐름은 별도로 코드를 만들어야 합니다. 카메라 영상이 들어올 때마다 AI를 호출해 좌·우 차선 위치를 찾고, 두 선의 중심점이 화면 한가운데에서 얼마나 벗어났는지 계산해 그 만큼 핸들을 꺾는 명령을 모터에 전달하는 **자율주행의 두뇌 노드**를 작성. 이 노드 덕분에 로봇이 차선 가운데를 따라 스스로 직진·곡선 주행 가능한 기본 상태에 도달했습니다.

## 7. 장애물 회피와 차선 추종의 통합 의사결정

차선만 따라가는 로봇은 앞에 장애물이 있어도 그대로 박는 문제가 있어, 거리 측정 센서(LiDAR)로 본 장애물 정보를 차선 명령과 합쳐야 합니다. 처음에는 두 기능이 한 노드에 섞여 디버깅이 어려웠는데, **인공 포텐셜 필드(APF)** 개념을 도입해 "차선 중심으로 끌어당기는 힘"과 "장애물에서 밀어내는 힘"을 가중 평균하는 합성 노드를 별도로 만들고, 차선·장애물·합성·제어 4개 노드로 책임을 분리. 한 기능이 망가져도 나머지에 영향을 주지 않아 각 기능을 독립적으로 튜닝할 수 있게 됐습니다.

## 8. 시뮬레이션과 실물 사이의 호환성 처리 (Sim-to-Real)

가상 시뮬레이션에서 잘 동작하던 코드를 실물 로봇에 그대로 올리면 메시지 형식 차이, 모터 보드의 옛 펌웨어, 카메라 색상 형식 차이 같은 자잘하지만 치명적인 문제로 한 줄도 작동하지 않습니다. 메시지 형식(Twist ↔ TwistStamped)을 환경변수 하나로 자동 전환하게 만들고, 모터 보드(OpenCR)의 펌웨어를 ROS1에서 ROS2용으로 교체하고, 카메라 색상 형식을 자동 변환하는 안전 가드를 추가. 같은 코드 한 벌이 시뮬과 실물 양쪽 모두에서 그대로 동작하게 되어, 두 환경 사이의 이식이 거의 자동화됐습니다.

## 9. PC ↔ 로봇 간 실시간 원격 모니터링

소형 로봇에는 모니터를 연결하기 어려워 카메라 영상이나 AI 인식 결과를 실시간으로 보고 튜닝하기가 매우 불편합니다. 같은 네트워크에서 자동으로 통신을 찾는 방식이 공유기 차단으로 작동하지 않아서, 로봇의 IP와 통신 포트를 명시한 설정 파일을 PC에 적용해 **PC에서 로봇의 카메라·추론 결과를 실시간 시각화**할 수 있게 만들었습니다. PC에서 영상 viewer 한 번만 띄우면 로봇이 보고 있는 화면 + AI가 그린 차선 박스 + 제어 명령 값까지 실시간으로 확인 가능해, 튜닝 사이클이 대폭 빨라졌습니다.

## 10. Docker Hub 클라우드 자동 배포 파이프라인

기존에는 PC에서 코드를 매번 로봇으로 동기화하고 컨테이너에 마운트하는 방식이라, 로봇이 PC에 종속되어 있고 코드 버전 불일치가 자주 발생했습니다. PC에서 ARM 칩용 이미지를 빌드해 **Docker Hub 클라우드로 푸시**하고, 로봇은 한 줄로 그 이미지를 다운받아 실행하는 파이프라인으로 전환. 코드와 AI 모델이 이미지 안에 내장되어 로봇 단독으로 어디서든 같은 환경을 재현할 수 있게 되었고, 시연 환경 이동 시에도 별다른 설정 없이 그대로 작동.

## 11. 모델 경량화 + AI 가속기 칩 전용 변환

처음 학습한 모델은 일반 PC GPU 기준으로 만들어진 형식이라 작은 로봇이나 전용 가속기 칩에서는 그대로 못 돌립니다. 입력 해상도를 절반(640→320)으로 줄여 연산량을 1/4로 감소시키고, 8비트 정수로 가중치를 압축(양자화)한 뒤, AI 가속기 칩(Hailo-8) 전용 실행 파일 형식(HEF, 9.5MB)으로 변환. 이 과정에서 모델 종류(yolov8s → yolov8n)와 입력 크기 조합으로 5번 시행착오를 겪었지만, 결국 가속기에 딱 맞게 최적화된 모델을 만들어 다음 단계인 속도 향상의 발판을 마련했습니다.

## 12. AI 가속기 칩(NPU) 하드웨어·소프트웨어 통합

작은 로봇의 CPU만으로는 AI 추론이 너무 느려(초당 2장) 실시간 자율주행이 불가능했고, 전용 가속기 칩(Hailo-8) 도입이 필수였습니다. 로봇의 확장 슬롯에 가속기 보드를 장착하고, OS 레벨의 PCIe 통신 속도 활성화(Gen3), 운영체제와 칩 사이의 다리 역할인 드라이버를 OS의 모든 커널에서 자동 빌드되게 설정, 그리고 컨테이너 안에서도 가속기를 사용할 수 있도록 칩 인터페이스를 통과시켰습니다. 이 통합 과정에서 7가지 호환성 이슈를 모두 해결해 이후 다른 사람들도 따라할 수 있는 35분짜리 설치 가이드 문서로 정리.

## 13. AI 가속기 전용 추론 노드 구현

가속기 칩이 만들어내는 출력 형식이 일반 모델과 완전히 달라서, 기존에 만든 차선 인식 코드로는 결과를 해석할 수 없었습니다. 가속기가 자동으로 끊은 두 출력(차선 위치 정보 + 신뢰도)을 받아 → 분포 기댓값으로 변환 → 표준 좌표 격자에 매핑 → 원본 이미지 크기로 복원하는 **후처리 모듈을 새로 작성**. 단위 테스트로 정확도를 검증한 뒤 기존 추론 노드와 똑같은 입출력 인터페이스를 유지해, **환경변수 하나로 가속기와 CPU 모드를 즉시 전환** 가능하게 만들었습니다.

## 14. 실주행 성능 측정 — 추론 속도 15배·실주행 FPS 2배

가속기 도입 효과를 객관적으로 확인하기 위해 두 단계로 측정했습니다. 먼저 가속기 단독 추론 능력을 측정해 **초당 217회 처리 + 1회당 4ms** 라는 베이스라인을 확보(이전 CPU 대비 15배), 이어서 실제 로봇 환경에서 카메라 입력을 받아 추론·제어 명령 발행까지의 전체 흐름이 **초당 30회 안정** 동작함을 확인. 가속기 사용률이 절반 미만이라 더 큰 모델 또는 부가 기능(시각화·로깅)을 추가할 여유도 충분히 확보했습니다.

## 15. 실세계 파라미터 튜닝 + 최종 시연

시뮬에서 잘 작동하던 파라미터를 실물에 그대로 가져왔더니 가속기 압축으로 인한 인식 신뢰도 분포 변화와 카메라 물리적 장착 오차 때문에 차선 외 영역에 박스가 잡히거나 좌우 진동이 발생했습니다. **신뢰도 임계값(0.12→0.85)** 을 높여 가짜 검출을 차단하고, **검색 영역**을 화면 하단 일부로 좁히고, **조향 게인**과 **이동 평균 필터**로 진동을 완화하며, 환경 기동·종료 스크립트에 NPU 자동 복구·모터 토크 자동 활성화 같은 예외 처리를 추가. 최종 시연에서 직선·곡선·장애물 회피·복귀를 모두 통과하는 자율주행 영상을 확보하고, 14주 프로젝트의 모든 단계를 시뮬레이션부터 실물까지 일관된 흐름으로 마무리.
